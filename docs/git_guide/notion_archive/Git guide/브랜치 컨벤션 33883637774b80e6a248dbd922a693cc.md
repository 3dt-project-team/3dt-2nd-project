# **🌿 Branch Naming Convention Guide**

## **1️⃣ 기본 원칙**

- 모든 작업은 **Issue 생성 후 브랜치 생성**
- 기본 브랜치는 dev
- dev 직접 push 금지 (PR 필수)
- 작업 브랜치는 작업 완료 후 PR merge → 자동 삭제

## **2️⃣ 브랜치 형식**

```jsx
type/short-description
```

예시

```jsx
feat/add-eventhub-trigger
fix/partition-key-error
hotfix/prod-timeout
chore/update-ci-workflow
```

## **3️⃣ type 종류**

| **Type** | **용도** |
| --- | --- |
| feat | 기능 추가 |
| fix | 버그 수정 |
| hotfix | 긴급 수정 |
| chore | 설정/구조 변경 |
| refactor | 기능 변화 없는 구조 개선 |

## **4️⃣ 작성 규칙**

### **✅ 규칙**

- 소문자만 사용
- 공백 대신 - 사용
- 너무 길게 쓰지 않기
- 의미가 드러나게 작성

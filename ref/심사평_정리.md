# SENSE 프로젝트 발표 심사평 정리

> **발표일**: 2026년 4월 17일  
> **프로젝트**: SENSE — Semiconductor Economic News & Sentiment Engine

---

## 1. 긍정 평가 (칭찬 포인트)

### 프로젝트 구성·기획
- **AI 대체가 아닌 지원 도구로 포지셔닝**한 점 — AI 위기감을 가진 청중을 배려한 메시지 방향 우수
- **범위를 좁게 잡은 전략 (삼성전자 + SK하이닉스 2종목)** — 기능 완성도에 집중한 현명한 선택
- **3가지 데이터 축(뉴스 감성 + 거시경제 + 수급·파생)** 혼합 활용에 깊은 인상
- **발표 후반부(팀 회고)** 내용이 "진짜 프로젝트를 제대로 해봤구나" 느낌을 주는 강력한 어필 포인트

### 기술적 완성도
- **Soft Switching 앙상블** 개념 — 신선하고 차별화된 접근법
- **Medallion 아키텍처와 데이터 전처리 단계 연결 설명** — 체계적이고 설득력 있음
- **ADF vs Databricks 전처리 비교 분석** — 실무적 근거를 갖춘 기술 선택 설명으로 매우 우수
- **Responsible AI 6대 원칙 항목별 적용 사례 설명** — 높은 평가 획득
- **Confidence Score 신뢰도 시스템 도입** — AI 자기 검열 기능으로 높이 평가
- **ADF 타이머 트리거 기반 전체 파이프라인 자동화** — 실용적 가치 높음

### 질의응답
- T+20 예측 기간 설정 근거, 이격도 120일 기준 설명 등 **근거 있는 기술 답변** 우수
- PostgreSQL 선택 이유(ADLS 분산 조회 한계, Azure SQL 오픈소스 활용도 비교) 논리적 답변

## 2. 개선 권고 사항

### 발표 구성·순서
- **발표 초반에 두괄식 배치 필요**: 듣는 중 의문점(뉴스가 근본 의사결정 동력이 될 수 있는가? T+20 기준 등)이 후반부에서야 해소됨 → **핵심 결론과 근거를 슬라이드 앞부분에 먼저 배치**할 것
- **자동화 사실을 초반에 강조할 것**: ADF 타이머 트리거 자동화는 비즈니스 가치가 매우 높은데 발표에서 묻힘

### 데이터 신뢰성·설명력 보강
- **감성 점수 구체적 예시 추가**: 점수 범위(-1~+1)와 분포, 실제 뉴스 예시와 해당 점수를 함께 제시하면 신뢰도 상승
- **피처 엔지니어링 기준 명확화**: 점수화 기준이 일반 지수에서 왔는지, AutoML 최적화 결과인지 구분 설명 필요
- **레짐 판별 기준 근거**: 데이터 기반 기준 외에 저명한 투자 전략가·논문 기반 근거를 추가하면 신뢰도 대폭 상승 (예: 워렌 버핏 투자 스타일 등 전문가 기준 연결)

### Responsible AI 보완
- **데이터 공정성(편향성 없음) 설명 강화**: 공정성 = 여러 종목 사용이 아니라, 수집·전처리 과정의 데이터 편향 없음을 구체적으로 제시
- **Confidence Score 기준 조정 가능성 명시**: 40점 기준을 고정 제시하면 사용자가 불편 → "투자 성향에 따라 조정 가능한 파라미터"로 설명하여 책임성 확보
- **포용성 확장**: 색약 대응 팔레트 외에 음성 안내, 시각장애인 대응 비전 서비스 등 접근성 기능 확장 아이디어 제시 권고

### 슬라이드 디자인
- **발표 자료 폰트 임베드 필수**: 발표 환경(PC)이 바뀌면 폰트가 깨질 수 있으므로 PPT에 폰트 포함 저장
- **앞뒤 슬라이드 디자인 일관성 유지**: 전반부·후반부 시각 스타일 통일 필요

## 3. 심사위원 질의 핵심

| 질문 | 답변 요약 |
|---|---|
| 반도체 사이클 반영 여부? | 평균 회귀 + 추세 앙상블로 상승·하락 양방향 대응, 뉴스 데이터로 선행 신호 포착 |
| 변동성 5일/20일 기준? | 5일/20일 **둘 다 사용**. `vol_ratio = realized_vol_5d / realized_vol_20d`로 단기 변동성 급증 탐지. 5일=노이즈·단기 모멘텀, 20일=불확실성 기준선 — 비율이 1.5 초과 시 AutoML 모델 가중치 강화 |
| 이격도 120일 기준? | 일반 주식 관례 기준 채용 후 AutoML 최적화 결과로 확정. 데이터 1년치 기준 최적값 |
| 감성 점수 구체적 예시? | (슬라이드에 제시 못함 — 보완 필요 인정) **실제 코드 기준**: `absa_score -1.0(매우 부정) ~ 0.0(중립) ~ +1.0(매우 긍정)`, 분류 기준 `≥+0.3 → 호재 / ≤-0.3 → 악재 / 그 외 → 중립` |
| PostgreSQL 선택 이유? | ADLS 분산 조회 한계 + Azure SQL 대비 오픈소스 활용도 우수 |
| AI 모델 선택 기준(비용)? | **GPT-4.1 mini** (gpt-4.1-mini) — 대량 뉴스 처리에 적합한 비용·신뢰성 균형. 향후 Plain Language 단계는 경량 모델로 대체 가능 *(주의: GPT-4o mini 아님)* |
